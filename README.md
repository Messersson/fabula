# Fabula 离线版（不打包 · 不依赖官方账号/API）

Fabula 是一个**纯本地 Web 写作应用**：
前端资源解包自官方 exe（原样未改），后端用 Node 零依赖实现替代 Rust 侧；
**AI 调用全部走你自己的 API（任何 OpenAI 兼容渠道）**，不连 mochang 的 hub，
不需要注册、不需要授权码、不产生任何费用到官方。

## 离线版 vs 官方版（重要差异）

- **无内置模型**：官方"内置免费模型/会员专供模型"依赖 mochang 服务器，离线版已整体移除（模型列表只显示你自己配置的渠道，"内置模型"区显示"暂无可用模型"）。
- **无登录/会员系统**：账号区显示本地身份"本地版"，不出现"点此登录/注册"、会员购买入口；欢迎弹窗自动关闭。
- 其余功能（AI 写作、书籍、技能、书源、导出等）与官方一致，全部本地运行。

## 快速开始

```bat
cd C:\path\to\Fabula
node server.js
```

浏览器打开 **http://127.0.0.1:17381/** 即可使用。
（双击 `start.bat` 也可以；`npm start` 等价于 `node server.js`。）

## 局域网访问与运行保障

- **默认不出网**：只监听 `127.0.0.1`，本机访问无需口令。
- **非回环绑定自动加口令**：`BIND=0.0.0.0 node server.js` 或 Docker 部署时，进程会生成一个访问口令（也可用 `FABULA_ACCESS_TOKEN` 指定）。首次访问带上 `http://<IP>:17381/?access=<口令>` 换取 HttpOnly 的 `fabula_access` Cookie，之后直接打开即可；口令错误返回登录页而不是页面内容。`/healthz` 例外，只返回 `{ok,uptime,db}`，供容器探活。
- **重启不丢断点**：启动时把上次遗留的 `running/retrying` 任务标成 `interrupted`（状态页可直接续跑），文档项目标 `failed`，有可用意见的评审轮次标 `paused`——不会出现「页面显示运行中、实际没人推进」的僵尸任务。
- **优雅退出**：收到 `SIGTERM`/`SIGINT` 后先停止接新连接，等待在飞请求与生成任务到安全边界（默认 10 秒，可用 `FABULA_SHUTDOWN_GRACE_MS` 调整），再关库退出；`docker stop` 不会硬切断 SQLite。
- **迁移前自动备份**：库内 `PRAGMA user_version` 记录 schema 版本；升级前用 `VACUUM INTO` 在数据库同目录生成 `writerx.backup-v<版本>-<时间戳>.db` 快照（保留最近 5 份），备份失败则拒绝启动，避免升到一半留下半套表。

## 把 API 换成你的（二选一，效果一样）

### 方式 A：修改 config.json（推荐，改完重启服务）
```json
{
  "activeChannelId": "ch_mine",
  "channels": [
    {
      "id": "ch_mine",
      "label": "我的API",
      "baseUrl": "填你的 OpenAI 兼容接口根地址",
      "modelsUrl": "可选：填你的模型列表地址",
      "model": "填你的模型 ID",
      "apiKey": "sk-你的密钥"
    }
  ]
}
```
- `baseUrl` 由用户自己填写 OpenAI 兼容接口的地址（DeepSeek / Kimi / 智谱 GLM / 通义千问 / 火山方舟 / MiniMax / 硅基流动 / OpenAI 都行）。
- 改完 **重启 node server.js** 生效（不会覆盖你在界面里改过的配置）。
- 也可以用 `modelsUrl` 自动拉取 /models 模型列表。

### 方式 B：界面里配（设置 → 渠道管理 → 添加渠道）
预设列表里已内置 9 个厂商（DeepSeek、Kimi、通义千问、智谱、火山方舟、MiniMax、硅基流动、OpenAI、自定义），
选一个 → 填 Key → 保存 → 设为当前渠道。应用内所有 AI 功能立即走你的渠道。

## 上下文与向量库能力

- 资料库仍是本地 Markdown 文件树；同时新增了本地向量知识库，数据保存在 `data/writerx.db` 的 `kb_files` 与 `kb_chunks` 表中。
- 正文按**场景**切片（360–1,200 字符，优先在空行与场景切换处断开），每片携带章号、出场人物、地点和关联伏笔；设定类文件仍按 1,400 字符、220 字符重叠切分。检索采用 SQLite FTS5 三元组全文索引与 256 维本地哈希向量的混合候选，再加实体/时间/伏笔过滤与重排。FTS 保住人物名、专有名词和原句，哈希向量补足周边词面关联；它不调用第三方 embedding 服务，书稿不会因索引离开本机。
- 检索打分在进程内的向量矩阵上完成（整书向量一次性装入连续 `Float32Array`），正文只按入选片段取一次；一本百万字长篇的热查询约 6–9 ms。索引变化通过版本号 + 短 TTL 失效，写入路径会显式丢弃矩阵。
- 文件保存、改名、删除会增量更新索引；章节摘要 Markdown 的追加只索引新增尾段，旧章修改时才全量重建。若发现片段数量与元数据不一致，追加会自动回退为全量重建。首次对话会自动补齐已有书稿的索引，也可调用 IPC `rebuild_knowledge_index` 强制重建整书索引。
- 全 AI 托管采用滚动规划：先根据《世界观》《人物库》《剧情大纲》生成当前 20 章窗口的 `章节规划.md`，再逐章生成细纲与正文；不会预先生成全书细纲，因此可随时中断并从下一章续写。
- 每章完成后会把摘要、人物/时空/事实/线索状态写入 SQLite；下一章同时参考上一章正文结尾、最近摘要、长期连续性状态和下一章细纲。人物上下文按核心人物优先并限制为最多 24 人；每完成 50 章会生成一卷摘要，供后续章节压缩回顾。
- 章节规划、章节摘要、连续性状态和卷摘要均按章或按卷落库；Markdown 文件仍是可编辑的本地副本，数据库负责长篇生成时的小窗口查询。批量续写默认保留任何非空已有正文，只有显式选择覆盖才会重写。
- 章节摘要追加前会记录旧文件长度并设置中断标记；如果进程在追加后、状态提交前退出，重启时会截断到旧长度后重放，避免重复章节。重写旧章时，人物、事实、时空和伏笔会按目标章节重放，不会混入后续剧情。
- 启动全 AI 托管前可以选择本书文风卡、主写法和最多 6 个叠加技能；这些配置会写入本书，之后章节规划、细纲和正文生成都会自动使用。
- 每次 AI 写作都会按当前请求和最近会话召回最多 8 个相关片段，最多加入约 10,000 字符；手动勾选的资料仍保留，最多 8,000 字符。
- 会话历史会附带最近 12 条用户/助手消息，每条最多 6,000 字符。
- 这套索引和分层记忆可支撑百万字小说的长期检索与渐进式写作，但不等于“百万字全文一次性塞进模型上下文”。生成时只装载当前规划窗口、最近摘要、长期状态、卷摘要和相关检索片段；建议总纲按“总纲 -> 分卷 -> 章节 -> 正文 -> 归档”维护，以便在数十万字后仍能稳定回收早期伏笔。
- 人物别称从《人物库》自动建立同义族（支持 `## 沈砚`、`## 沈砚（墨七）`、`## 沈砚 | 墨七`、`**沈砚**（墨七）`、`- 别名：墨七、断水客` 等写法），查询时双向展开，所以正文只写「墨七」也能被「沈砚」召回。
- 当前哈希向量是本地词面相似度，不是语义 embedding，因此纯同义改写和隐喻关联仍可能漏召回。
- **语义召回（可选，embedding 叠加层）**：在设置里配置 `embedding_model`（走你当前渠道的 OpenAI 兼容 `/embeddings`，如 SiliconFlow 的 `BAAI/bge-m3`、`BAAI/bge-large-zh-v1.5`，也可用 `embedding_base_url` / `embedding_api_key` 覆盖地址与密钥）即可启用。片段向量懒填充进 `kb_embeddings` 表（首次检索顺手补齐，或调 `prime_embeddings` 一次性预热）；全书片段都有同一模型的向量后，检索的"向量分量"自动切换为语义余弦，与 FTS 词面分、人物/伏笔命中继续混合打分。任何一步不可用——未配置、接口失败（60 秒断路冷却）、只填充了一部分——都整本无缝回落到本地哈希引擎，两个向量空间绝不混算；换模型时旧向量自动清空重填。IPC：`get/set_embedding_config`、`prime_embeddings`。选型说明：本地跑 bge-small-zh 需要引入 onnxruntime 等原生依赖，与本项目"零 npm 依赖、纯离线"的约束冲突，因此选择走你已配置渠道的 embeddings 接口（bge 系列在各聚合网关通常免费或近似免费），哈希引擎作为永远可用的兜底。

## 无人值守长跑

批量生成正文（`batch_generate_bodies`）和全 AI 托管（`batch_generate_full`）都支持长时间无人值守，相关参数：

| 参数 | 默认 | 作用 |
|---|---|---|
| `recoverMode` | `auto` | `stop` 任一章失败即停；`skip` 隔离后永不因单章失败停；`auto` 隔离后继续，连续失败达到阈值才停 |
| `maxConsecutiveFailures` | `2` | `auto` 下的停机阈值。单章失败多半是这一章的问题，连续失败多半是渠道/配额/上下文问题 |
| `maxRetries` | `3` | 每章的重试次数（指数退避，尊重接口返回的 `Retry-After`） |
| `escalateRetry` | `true` | 重写时把上次被判不合格的原因写回提示词，而不是原样再问一遍 |
| `maxTokensPerChapter` | 目标字数 × 1.5 + 8000，再 × 6 | 单次尝试的 token 上限，用于识别「越写越长」的失控；触发后该章隔离且不重试 |
| `maxTokensPerRun` | `0`（全托管为 800 万） | 整轮 token 上限；超限时**保留断点暂停**（`paused_budget`），可续跑而不是失败 |

- **状态页**：浏览器打开 `http://127.0.0.1:17381/status`，可以看到每个任务的状态、进度、token 消耗、被隔离的章节及原因，并直接点「从断点续跑」。页面 15 秒自动刷新，由服务端直接渲染（不依赖前端构建产物）。
- **续跑**：`resume_generation_run` 会从第一个未提交的章节继续，把被隔离的章节重新排队，并复用原来的任务（token 账目和失败原因不会断成两段）。已提交的章节不会被覆盖。
- **生成日志**：每轮结束（含取消和异常）都会把结果追加到作品的 `设定/生成日志.md`：新建/跳过几章、哪几章被隔离及原因、花了多少 token、为什么停机。
- **一致性审计**：每 10 章做跨章审计、每 50 章做卷级审计（跨章重复桥段、章末钩子缺失、核心人物断层、篇幅漂移、未回收伏笔积压、**世界规则禁词**、**正典事件复现**），结果追加到 `设定/一致性报告.md`。审计只报告，不阻断生成。
- **世界规则 / 正典事件**：两张硬约束表——`世界规则.md`（全书不得违背的设定铁律，可附 `禁词：` 供审计逐字排查）与 `正典事件.md`（已锚定章节的正典事件，后续章节不得矛盾或复现，`关键词：` 供卷级审计检测远期复现）。文件在作品的 `设定/` 组里直接编辑，也走 IPC（`get/save/delete_world_rule`、`get/save/delete_canon_event`）；**全托管与 AI 共创两条路径都自动注入**（细纲/正文批量、自由对话、智能写作、场景生成；未来章节的事件不提前泄漏，自由对话取"站在最新进度"视角）。交互保存正文（save_doc / save_section）会自动补齐长期记忆（章节摘要/连续性），与批量路径共享同一套世界状态。审计确定性排查禁词与事件复现；禁词 ≥2 字、指纹短语 ≥6 字，否则容易误报。
- **500 章端到端仿真**：`test/longform-simulation.test.js` 用桩模型把全托管状态机连跑 500 章验证到底——中途注入单次失败升级重试（第 50/150/400 章）、永久失败隔离（第 100/300 章）、两次预算暂停与续跑收尾，断言 500 章全部提交、三段共用同一个任务、token 账目与桩的实际调用次数分毫不差、已提交章节零重做。`npm test` 在开发机上约 2~4 分钟（视机器而定），其中这场 500 章仿真占大头。
- **测试规模**：356 个测试（355 通过 + 1 条 POSIX 专属的优雅退出测试在 Windows 跳过；文档域 186 条 + 评审机制 49 条），其中评审机制的 49 条覆盖开关三级、评审团组建/编辑/独立性提示、并发独立评审、共识与分歧仲裁、可行性评估、落改与前后对比、暂停/继续/终止、小说多评审对象、自动进入评审、Skill 绑定/权重/停用、蒸馏优劣势必填与去重、自定义文档类型、每轮 token 预算切分与超限拒绝、评审调用失败重试；另含「模板严格沿用」7 条回归（层级/篇幅不被文本框冲掉、作者另写结构时不硬套层级、提示词不同时下达相反指令、正文编号行规范化、导出带目录域且标题层级取自模板、目录可按模板重新同步、页面模板卡可见），「质量基准与证据链」13 条回归（论证层检测、依据密度硬缺陷、空话分级、论点—证据对应、动作描述不算论点、基准进提示词、论点落库与对照表、评审带系统缺口、多轮深审双维度收敛、上下文继承、体检聚合、页面基准卡、目标字数不低于下限），「百万字级上下文」16 条回归（索引与增量同步、百万字里命中只出现一次的数据、装配结果有界、语料地图、作者指定素材、文档记忆不膨胀、素材删除同步清理、近似去重、小说检索链路不受影响、稀有词门槛挡住无关主题、同模板不同数据不被去重、评审看到全部素材编号、用量落库并上页面、事务可重入、多主题覆盖）。另有 3 条启动冒烟（干净数据目录拉起真实服务，五个页面 200、`/healthz` 探活、官方技能已播种）、9 条访问门禁（5 条纯函数 + 4 条真服务非回环：未带口令 401、错口令、`?access=` 换 Cookie、healthz 放行）、4 条启动恢复与迁移备份、1 条优雅退出（POSIX 上验证 SIGTERM 退出码与关库日志，Windows 跳过）、4 条离线书源测试（本地 HTTP 桩验证搜索/目录/正文清洗/失败处理，不依赖公网）。另有 `scripts/e2e-template-lock-check.cjs` 生成模板绑定文档供 Word COM 实测（目录域、Heading 层级、字体字号、页边距逐项核对）。
- **可复现**：种子库与默认提示词/书源/敏感词随代码放在 `resources/`，干净检出（没有 `data/`）即可直接 `npm test` 与 `node server.js`；Docker 镜像同样自带这些资源。

## AI 评审机制（多厂商评审团）

入口：`/review`（页面顶部可在「文档工作台 / 小说工作台」之间切换）。文档侧有两个入口：每节的「🧑‍⚖️ 评审团」卡、左栏底部「评审团」；小说侧在主界面标题旁注入「🧑‍⚖️ 评审团」胶囊（官方前端无源码，只能靠 `lib/glue.js` 注入）。**默认关闭**，开关按工作台、按文档类型独立生效；15 种内置类型与「自定义」文档类型各有自己的开关，「自定义」也会出现在类型级列表里，否则自定义稿永远无法单独配置。

- **评审团**：1~3 位评审员，每位绑定一个已配置的渠道。
  - **这一轮用哪个团，作者当场挑**：作品页有「这一轮用哪个评审团」下拉，类型匹配的团标「默认」但不强制。预设只是默认值。
  - **厂商/模型标识跟随渠道自动生成**：渠道顺序决定「厂商甲/模型 X」这类通用标识，同一渠道在任何团里标识一致，不写入真实厂商名（方案四：仅用于区分能力差异）。**渠道必须互不相同**——同渠道的两位评审员只是同一模型自评两次，那不是多厂商评审，是双倍账单。成员可随时换人、增删，按类型绑定预设（「论文用学术团、小说用创作团」）。
  - **建好的团可以原地改**：名称、成员、轮次上限都能编辑，页面预填现有配置；保存复用同一个团而不是偷偷新建。两个渠道指向同一服务地址与模型时保存直接拒绝——换一把密钥仍然是同一个模型自评两次；成员绑定的 Skill 互相打架（「三句话短评」+「逐项详评」）也在组建时就提示，而不是等跑完付过账单才发现。
  - **小说侧评审对象可切换**：章节 / 全文 / 世界与人物设定 / 细纲 / 番外各自独立成「作品」，轮次按对象分别编号、互不串号。页面上的「切换评审对象」会把每个对象的文件列出来，设定与细纲不再只能整本评审。
- **独立性靠结构保证，不靠提示词**：每位评审员各自一次调用、各自一份提示词，互不可见；汇总发生在全部返回之后。测试断言了「甲的人设不会出现在乙的提示词里」。
- **结构化意见**：评分/等级/总体评价/亮点（含为什么好）/问题（致命·重要·一般 + 维度 + 位置）/修改建议/优先级/本轮聚焦。提示词明确要求每条问题必须指出位置并给出一条可执行改法，禁止「可以更深入」这类空评语。
- **开关完全由用户掌控（三级）**：全局 → 工作台 → 文档类型，页面上逐级可见、逐级可改。
  - **关闭是硬的，开启是软的**：上一级关掉，下级一律关闭，不能被下级的「显式开启」绕过——否则「关掉整个文档工作台」之后，之前单独开过的「申报书」还在跑，用户会认为开关失效。
  - 类型级支持三态：开启 / 关闭 / 跟随上一级；「跟随」这一档必须能清回去，否则一旦设过关就再也回不到继承状态。
  - **本次生成也能选**：全托管生成按钮旁有「送评审团」勾选（与左侧的「六维打分」明确区分——前者是多厂商评审团，后者是单模型自评）。取消勾选只跳过这一次，不改总开关。机制未开启或没配评审团时这个勾选不显示——显示一个勾了也没用的框是骗人。
- **暂停与终止**：运行中的轮次可以立即终止（真的打断在飞的模型调用，不是只把进度条停住）；已产生的意见与版本完整保留，状态标为「已终止」。规范里这一条最容易做成假的——只改状态不打断调用，等于用户点了「终止」但账单还在涨。**暂停是另一件事**：请求暂停后，本轮已发出的评审员调用会跑完再停，已产出的意见原样保留、可逐条查看；点「继续这一轮」直接从汇总阶段接着走，**不重新调用评审员**，所以不会为同一批意见付第二遍钱。已经开始汇总/仲裁的轮次不允许暂停（汇总到一半暂停会丢掉已完成的仲裁），页面会建议等它完成或直接终止。
- **可行性评估**：采纳之前对照**作者意图**（文档取项目说明/论题/论据/本节要求，小说取题材与视角）判断「这条意见该不该执行」。与意图冲突的意见即使评审员说得有道理，也判为不采纳并写明理由——否则一篇 800 字短评会被要求补数据，一份内部通知会被要求加文献综述。
- **轮次上限**：评审团可设「最多几轮」（0=不限），达到后不再起新一轮；报告标「已达设定轮次」。
- **评分变化**：每轮记录上一轮均分与差值（第一轮为 —），否则只看单轮分数看不出「改完有没有变好」。
- **修改前后对比**：落改前后各留一份正文（`review_rounds.before_text / after_text`），报告里可直接对照，而不是只给一个字数差。
- **默认 Skill 组合**：某一类 Skill 没配时自动补默认组合（文档/小说各一套，写在代码常量里，不会被误删）。没有默认组合时，未配 Skill 的评审员会退化成「你看着审」，输出一堆「可以更深入」式空评语。
- **交叉验证**（`lib/review-engine.js` 的 `crossValidate`）：
  - **共识合并**：两位以上评审员换着说法提同一问题，合并成一条并标注共识。判据不是单纯比文字相似度——实测「论证过简」与「论证过简，缺少机制」相似度 0.333，而「论证缺少机制」与「论证缺少数据支撑」反而 0.429；任何单一阈值都会同时犯「漏合并」和「误合并」两种错。改成「问题类型（缺/冗余/不一致/格式）+ 核心词重合」判定。
  - **分歧识别**：方向相反的意见（过简 vs 冗余）相似度很低，一定落在不同簇里，所以分歧检测必须在**簇之间**做，否则两条互斥指令会一起被采纳。
  - **多数倾向就地裁决**：2 票 vs 1 票直接采纳多数、把少数意见写进理由。
  - **平票回抛给评审团复评**（方案六）：1 票 vs 1 票时，把两种相反意见的原文摆给评审团每位成员，各自判「哪边更站得住」，票多者胜出；只有复评仍平票才退回单一「评审组长」裁决。裁决应该来自评审团内部的分歧收敛，而不是外部权威。
  - **单人意见**：致命/重要问题采纳，一般问题只记录。
- **落改**：只把采纳的意见转成逐条修改指令（「改哪个段落、改成什么」），不采纳的不会混进指令；整篇评审不自动落改（跨节修改要逐节确认，避免「一键改全文」把好段落改坏）。改前改后都有版本记录。
- **评审库（Skill）**：三类 Skill——评审技能（怎么审）/ 评审风格（怎么说）/ 评审重点（审什么）；声明适用范围（`novel` / `doc` / `doc:paper` / `*`）自动匹配。风格与技能冲突会提示（「三句话短评」+「逐项详评」同时配，评审员只会执行一个）。
  - **Skill 可编辑、可停用**：停用后不再参与任何评审匹配，但管理页仍可见（可随时启用回来）。直接删除会让历史轮次里「当时用了哪条 Skill」失去线索，停用只是退出匹配，历史记录还能对上。
  - **可以把 Skill 配给具体评审员**（`review_reviewer_skills`）。这一条是方案里「给编辑配这三条、给读者配那三条」的落点：学术审稿人只看论证完整性、格式审查员只看引用规范。**按类别排他**——某位评审员在某类上被绑定过，该类就只用绑定的那些，不再自动并入共享池；否则两人最终拿到同一套标准，多厂商评审退化成三个模型用同一把尺子。
  - **维度权重可配置**：Skill 上填 `论证论据=2, 逻辑结构=1.5`，评审员会被要求按维度分别给分，**总分由系统加权算出**，不采信它自报的总分（模型自报 95、分维度却是 60/90 的情况很常见）。没填权重就是各维度等权，退回模型总分。
- **蒸馏**：贴一篇优秀作品（或从历史高评分作品一键选）→ 提炼**可迁移的检查项**（「引言须在 300 字内交代研究问题与创新点」），而不是复述这篇作品。
  - **优劣甄别（硬性）**：要求模型同时写出「样本里有、但不值得标准化的写法」；写不出来说明它没甄别、只是把全文抽象了一遍，这次蒸馏直接拒绝入库。优秀作品里也有凑字数的过渡和模板化开头，照单全收会把噪声固化成规则，之后每个评审员都拿它扣分——比不蒸馏更糟。
  - **入库冲突校验**：同类别、适用范围有交集且名字或正文相似度 ≥0.72 时拒绝入库（重复的 Skill 不会让评审更准，只会让同一件事被扣两次分）。
  - **推荐蒸馏源**：历史评审均分 ≥70 的小节自动出现在「推荐蒸馏源」里，一键蒸馏，不必手工翻找和粘贴。
- **可追溯**：每轮落 `review_rounds`（轮次、版本哈希、状态、均分、是否收敛）+ `review_opinions`（每位评审员的完整意见）+ `review_decisions`（每条意见的采纳与否与理由）。「连续两轮没有新增有效意见」会标为已收敛。
- **容错**：某位评审员返回垃圾或调用失败，整轮不失败——其余意见照常产出，失败原因显示在报告里（一位评审员挂掉就整轮重来，是最贵的错误处理方式）。
- **成本护栏**：每个评审团可设「每轮 token 上限」（0=不限，未设时每位评审员默认 3000）。设了预算就按人数均分单次 `maxTokens`；总量低于「人数 × 600」直接拒绝开跑，而不是让模型写到一半被截断、再拿半截意见去打分。连接类失败（429/5xx/超时）自动重试一次；预算模式下「返回不可解析 JSON」不重试——那一次调用已经花满 token，再打一次就是双倍账单。评审页团的胶囊直接显示「每轮 ≤ N tokens」。
- **自动进入评审**：开启后，文档整篇生成完成时对**新写的小节**各跑一轮，小说批量生成完成时对**新写的章节**各跑一轮（只出意见、不自动改稿，且只跑一轮）。自动改稿意味着「AI 未经确认就改了你的正文」，自动连跑多轮会在作者离开电脑时把账单翻几倍——这两件事都该由作者在轮次页显式决定。小说侧这一轮还可以按次取消（「送评审团」不勾），不改总开关。
- **与架构的关系**：评审引擎不认识「文档」或「小说」，只处理「作品」抽象（`resolveWork` 提供读写适配器）；模型调用全部复用现有渠道配置（`llm.channelList()` + `channelKey()`），没有新增调用层。

## 文档工作台与技能广场

小说之外的第二条产品线，与小说创作完全隔离（平行引擎、平行页面，小说管线一行未动）：

- **入口**：主界面右下角常驻 dock（文档工作台 / 技能广场 / 任务状态），或直接访问 `http://127.0.0.1:17381/docs`。
- **文档类型**：**15 种内置类型 + 自定义**，按下拉框分组（学术研究 / 商业与投资 / 项目与申报 / 工作与行政 / 产品与技术 / 传媒与演讲 / 法律与合规 / 自定义）：
  - 学术研究：学术论文
  - 商业与投资：商业计划书、可行性研究报告
  - 项目与申报：项目申报书、投标文件
  - 工作与行政：调研报告、工作总结与述职、会议纪要、通知公告（公文）、制度与管理办法
  - 产品与技术：产品需求文档（PRD）、技术方案设计
  - 传媒与演讲：新闻稿、演讲稿
  - 法律与合规：法律合同（共创建议）
  每种类型都带**自己的小节结构 + 篇幅下限 + 文风要求 + 专属硬约束**（`DOC_TYPES` / `TYPE_RULES`）。加类型的门槛是三条都成立：结构真的不同（纪要不是短一点的报告）、有专属硬约束（否则只是换标题）、篇幅量级符合实际（公函 1500 字够了，可研没有 6000 字撑不起来）。不需要公式/图表的类型（纪要、通知、制度、新闻稿、演讲稿、合同、总结）不会注入公式规则，段落计划的图表上限也会被压到 0——约束用错地方就是反向引导。
  自定义类型上传模板（.md/.txt，按 Markdown 标题或中文序号切分小节；浏览器本地读取后提交，不经第三方）。
- **两种写作方式**（工作台头部随时切换，已有正文两种方式都不覆盖）：
  - **AI 共创**：逐节对话——AI 先追问、作者回答、信息够了才成稿；成稿与对话同屏，正文按 Markdown 渲染。也可「AI 起草本节」「AI 续写下一节」或直接手写。落稿前过同一套门禁（过短 / 疑似 JSON / 代码围栏一律不落稿），一次不达标会带着失败原因重写一次。
  - **AI 全托管**：整篇批量，逐节质量门禁、失败隔离、连续失败停机、token 预算暂停、断点续跑——与小说管线同一套 orchestrator 状态机与语义。跑完在工作区「本轮报告」里给出每节状态、失败原因与 token 消耗；同一项目不允许并发起两个任务，续跑沿用原任务与原预算。运行中可点「■ 停止生成」：当前小节写完后停下，已完成的小节保留、可随时续跑，不必等整篇跑完或杀进程。
  - 合同草稿仅作辅助，页面与导出文件均提示签署前需专业人士审核。
- **素材通道**（工作区「📚 素材」卡）：粘贴或上传文献摘要、行业数据、政策条文、团队履历，并填作者/年份/出处。按节检索后注入提示词（中文二元字组相似度打分，只保留不低于最高分 50% 的片段，单节上限约 2000 字）。提示词里明确「素材是唯一可用的事实来源」——素材没覆盖的地方写【待补】而不是编造。
- **素材编号稳定**：编号在加入时定下（项目内自增，删掉的号不复用）。按「当前排序位置」现算编号会让作者写完正文再补一条素材时，所有 `[M1]` 整体错位、参考文献全乱——而且看不出是哪一步坏的。
- **引用与参考文献**：素材带全文稳定编号（`[M1]`、`[M2]`…），正文引用后导出自动生成参考文献页。**参考文献按正文首次引用顺序编号**（学术惯例），内部编号在导出时自动换成论文序号 `[1]`——正文里出现工单号是不能交的。著录按 GB/T 7714（`[1] 张三, 李四. 题名[J]. 工业经济 2023(4): 12-19.`）或 APA 排版，文献类型标识按素材类型给 `[J]/[R]/[A]/[Z]`。体检会单独报「引用了不存在的编号」——模型编造引用是论文最容易被一眼看穿的错误。
- **论文要素**（工作区「📄 论文要素」卡）：作者、单位、中英文题名、关键词、中图分类号、基金项目、参考文献体例。导出时排在题名下方，就是投稿首页那一整套——缺这些不是「写得不好」，是投稿系统直接退。
- **文献接入**（工作区「📖 文献」卡）：导入 Zotero / EndNote / 知网的 **BibTeX（.bib）/ RIS（.ris）/ CSL-JSON（.json）**，一条文献自动变成一条带作者、年份、出处、DOI 的素材；LaTeX 重音（`M{\"u}ller`）会转成纯文本，重复条目自动去重，没摘要的条目会明说「没有摘要」而不是让模型去猜。在此基础上生成**文献矩阵**（方法 / 样本 / 主要结论 / 局限，摘要没写的标「未提及」），一键插成三线表，或直接生成**文献综述初稿**——综述只能引用矩阵里出现过的编号，不得引入矩阵外的文献，矩阵里写「未提及」的字段正文不许替它补。这是「文献综述有真实地基」的唯一可靠路径：模型不可能凭记忆给出真文献，那只会编。
- **文体专项**（工作区「🧰 文体专项」卡）：四类文档的「高质量」标准完全不同，所以约束和工具都按类型给，不搞一套提示词通吃。
  - **商业计划书**：财务模型。把假设（客单价、客户数、增长率、成本率、税率、资本开支、融资额）当输入，代码算出**利润表 / 现金流量表 / 收入预测 / 单位经济 / 融资测算**五张表并插进正文。三表内部闭环（期末现金 = 期初 + 经营 + 投资 + 筹资），LTV/CAC、获客回本周期、稀释比例全部算出来；现金流为负时会直接写出缺口，不让「利润表赚钱但现金流断裂」这种矛盾过关。假设存库，改一个增长率可一键重算。
  - **项目申报书**：考核指标表（指标 / 基线值 / 目标值 / 验收方式，目标值不含数字会被标为「不可考核」）与经费预算表（科目 / 金额 / 占比 / 测算依据，占比与合计自动算，缺依据标【待补】）。
  - **法律合同**：按内容自动识别合同类型（买卖 / 服务 / 劳动 / 租赁 / 合作），生成**必备条款对照表**（逐条标「已具备 / 缺失」并说明缺失风险），并做风险扫描——缺必备条款、单方权利表述（「有权单方面变更」）、模糊表述（合理 / 适当 / 尽快）、违约责任没给比例、争议解决没指定机构。
  - **调研报告**：样本构成表（按任意列分组，频数 / 占比 / 累计占比自动算）——结论能不能信，先看样本。
  - 每种类型各有自己的**类型化写作约束**进提示词（论文必须可证伪、BP 必须给财务假设与市场推算、申报书目标必须可考核、合同禁止单方权利与模糊表述、调研报告必须交代样本与方法、可研必须做敏感性分析、PRD 必须可验收、技术方案必须做选型对比、纪要决议必须可执行、公文依据必须给文号），专项检查结果也会进全文体检。
- **素材检索（BM25 + 同义扩展）**：`lib/doc-retrieval.js`。二元字组当词、项目内 IDF、BM25 长度归一、标题加权、30 组领域同义词扩展。换掉原来的「裸二元字组计数」，是因为那个算法有三处硬伤，每一处都直接让稿子写空：**没有 IDF** 时「企业」「进行」和「回收期」同权，检索出来的永远是泛泛段落；**没有长度归一**时越啰嗦的素材越容易被选中；**没有同义扩展**时查「回本周期」检索不到「投资回收期」——明明有素材，模型只能写【待补】。
- **定点修补（替代整节重写）**：评审要求给出 `patches`（逐字摘录的问题句 + 改写），只替换被指出的那几句。整节重写的问题是「六段里一段有问题，重写后五段变差一段变好，净收益接近零」。摘录对不上、或同一句出现多次时**宁可不改**，退回整节重写兜底。
- **续写接缝裁剪**：续写时注入「已经讲过的要点」（首句清单），防止绕回去把前面讲过的再讲一遍；拼接时做最长重叠裁剪 + 末句相似度判断，把模型「先抄一遍上一句再往下写」的重复裁掉。原来只查开头 80 字完全重复，换个说法就漏过去了。
- **两种写作方式共用同一条能力链**：共创（`mode='co'`）逐节起草/对话修改，全托管（`mode='auto'`）批量推进；差别只在「谁触发、要不要逐节评审」，**能力不打折**：
  - 起草任何一节，提示词都会带上段落计划、必答子问题、深度档位、按节检索的素材、图表占位、公式约定、证据规则
  - **文献综述类小节**（标题含「文献/综述/研究现状/理论基础」）自动注入文献矩阵，综述才有「按方法分组、指出共同缺口」的骨架
  - **自动分析预设**指定的那一节（通常是「结果与分析」）自动跑统计，把系数表注入提示词，正文写完后自动补三线表——全托管批量跑的时候不需要人守着点分析
  - **全托管开始批量前**：有文献素材但还没矩阵，自动生成一次（失败不阻断）
  - **全托管整篇写完后**：自动跑方法论审查（单节评审看不出「有没有识别策略」，这是跨节判断）
- **方法论审查**（工作区「🔬 方法论审查」卡）：写作评审看文笔，这张卡看研究设计。两层：**规则扫描**（零成本、可复现）检查八项——研究问题、抽样与样本量、变量测量、识别策略、稳健性、内生性、伦理、结论边界，其中「用了因果表述（导致/带来/显著提升）却没有识别策略」单独报警，这是最容易被一票否决的一条；**模型审查**按同一份清单逐条给「做到 / 偏弱 / 不成立 / 未交代」与可执行的下一步，并单列「会被直接拒」的问题。
- **数据表与统计分析**（工作区「📊 数据表」卡）：上传 CSV/TSV（第一行列名），选变量就能跑描述性统计、相关系数矩阵、OLS 回归（含 HC1 稳健标准误）、分组 t 检验（Welch，不假设方差齐性）。**系数、标准误、t 值、p 值、R²、F 全部由 `lib/doc-stats.js` 算出**，模型不参与计算——它最多把结论写顺，改不动任何一个数。结果直接排成**三线表**（顶线、表头线、底线，无竖线）插入本节，并自动生成引用真实系数的结果段；表号全文连号，结果段里的「表 N」会换成真号。统计实现零依赖：正规方程 + 高斯-约当求逆，p 值走不完全 Beta 函数，t 分布与 F 分布都与教科书值对过。设好**自动分析预设**（哪一节、哪份数据、因变量是谁）后，起草到那一节会自动跑、自动补表。
- **数字溯源**：正文里的数字必须能在素材、图表或统计表里找到出处，否则体检报「数字无来源」。模型顺着语境编一个「73% 的企业」是论文最危险的一类错误——编引用会被查出来，编数据不会。素材里「128、186、242、298 万元」这种单位后置的枚举写法会逐个登记；素材写「3.2 万」而正文写「32000 元」也视为同一个数；「在 1% 水平上显著」不会被当成数据。
- **成稿体检**（不调模型、零成本）：跨节重复段落 + **近似重复**（换个说法重复同一段，二元字组相似度 ≥72%）、篇幅塌陷、`【待补】`统计、论据是否写进正文、引用编号是否存在、图表与占位符是否对得上、**图表与表格是否被正文呼应**（「如图 1 所示」「如表 1 所示」）、**数字是否有出处**、**公式定界符是否配对**、必答子问题是否被绕开。只出报告不阻断——「合格」没有可判定的阈值，硬门禁只会让无人值守直接停死。
- **模板蒸馏与严格沿用**（工作区「🧪 模板蒸馏与拆解」卡 + 新建弹窗「📚 已蒸馏模板」）：
  - **蒸馏**：上传一篇写得好的样例 `.docx`（或粘贴全文），服务端用 `lib/docx-probe.js` **实测**它的章节目录层级、字体、字号、行距、首行缩进、页边距、编号规则，再让 AI 只补每节的写作要点与文风技法。实测值优先于模型猜测——纯文本里没有字体信息，让模型猜字体字号，猜出来的永远是「常见值」。蒸馏产物存为命名模板，同时沉淀为一条 doc 域技能。
  - **提交模板后直接在模板里写**：选中模板建文档后，**章节目录、层级、每节篇幅下限与要点、字体字号行距页边距、写法要点全部取自模板**。作者改标题时只改标题，层级与篇幅仍然以模板为准（`mergeTemplateSections`）——否则「目录看着像模板，排版层级与篇幅其实不是」，这正是"严格沿用"最容易破功的地方。
  - **写作时锁死目录**：模板模式下提示词明确禁止模型输出任何小节标题或「一、」「（一）」「1.1」编号，节标题一律由系统按模板统一添加；模板模式下排版提示词也不再教模型「用 Markdown 写小标题」——两条相反指令同时下达，模型只会挑一条执行。
  - **正文规范化**：模型偶尔还是会写「一、现状分析」这类编号行，导出前会被剥掉编号并降为「正文小标题」样式，避免与模板节标题的编号撞车、让读者以为目录被改写。单层 `1.` 视为有序列表项，不误伤。
  - **导出严格一致**：Word 导出时标题按模板层级映射 Heading1~3 并按模板编号规则加前缀（`一、` / `（一）` / `1.1`），正文前自动插入 **Word 目录域（TOC）**，`settings.xml` 写 `updateFields`，打开即可看到与模板一致的导航结构；模板绑定时正文里的模型自写标题不进目录。
  - **锁定与显式解锁**：版式随模板锁定（要改必须先显式「解除模板绑定」，把"我不再照模板写"这件事做成一个动作）；模板被重新蒸馏后可用「↻ 重新套用模板目录 / 版式」一键对齐。工作区「📚 模板」卡随时显示当前模板名、完整目录（带层级）与注入的写法要点。
- **写作流水线**（两种模式共用，借鉴同类开源项目的做法）：
  - **深度档位**（简洁 / 标准 / 深入，项目级设置，头部随时切）：档位不是形容词，是四个可执行的量——篇幅下限乘数（0.75 / 1 / 1.4，乘在 `doc_sections.base_chars` 基数上，来回切不漂移）、段落计划段数（2~4 / 3~6 / 5~8）、每节必答子问题数（1~2 / 2~3 / 3~4）、配图上限（1 / 1 / 2）。切档位会作废旧段落计划（骨架变了），但已写正文不动。
  - **段落计划**（借鉴 LongWriter 的 AgentWrite）：起草前先出「每段写什么、多少字、用哪条素材」，落库复用；重试不换骨架。计划同时产出**本节必须正面回答的子问题**与**图表 spec**，两者都随计划进提示词。
  - **图文并茂**：计划阶段从素材里已有的数字定出图表 spec（柱/线/饼，类目 ≤8、系列 ≤3），落库 `doc_sections.figures_json`；正文只在合适位置单独一行写占位符 `【图N：标题】`，数字不在正文里重新生成——「图文并茂」不会变成「模型现场编数据」。素材没有数字就不出图，宁可没图也不要一张全是 0 的柱状图。三路渲染同一份 spec：页面内联 SVG（矢量、可缩放、无图片服务）、Word 原生 DrawingML 图表（`word/charts/chartN.xml`，不引 xlsx，Word 打开/打印/转 PDF 正常）、Markdown 降级为表格 + 题注 + 资料来源。全文图表跨节连号（第 2 节的第一张图叫「图 3」），占位符跟着改号；对不上数据的占位符原样保留在页面上，不静默吞行。
  - **字数缺口补写**：一次只写到目标的一半时，让同一位作者接着写剩下的段落，而不是整节重写（重写只会换一套结构，还更贵）。拒答/半句这类「根本没写起来」的不会被接长，直接判失败重来。补写有两个驱动：篇幅不够，以及**计划里的论点没写出来**（字数够了但某段论点没兑现，字数门禁是过的、稿子却是空的）——后者最多补一轮，补不出来说明素材撑不起这个论点，交给评审判，不硬编。
  - **论点—证据对应（证据链）**：段落计划阶段就要求模型为每段给出 `claim`（可被反驳的判断句）与 `evidence`（素材里的哪句话/哪个数字支撑它），随计划落库。起草提示词里以「论点—证据对照表」列出，写作者知道每段要证明什么；评审逐条核对论点有没有被讲出来、有没有挂上对应素材编号，未兑现的进 `unsupported` 并触发修订。`claim` 的判定有白名单约束——「提出本节的核心判断」这类动作描述不算论点，否则每节都会被判「论点未兑现」并触发无谓补写（假缺陷比不检查更有害）。
  - **质量基准（`lib/doc-benchmark.js`）**：把「写得深不深」从形容词变成可测的量。按文档类型定义硬指标（论文每千字 ≥1 条带编号依据、论证层 ≥3；通知/纪要不需要引用就不设这条），用正文里可查的特征检测四件事——**论证层数**（机制/对比/边界/推进，靠措辞强信号识别）、**依据密度**（有素材却一处 `[M编号]` 都没有）、**空话**（「随着…的发展」「众所周知」等）、**论点兑现**（二元字组覆盖率匹配计划论点，再看该段有没有引用对应素材）。基准有三个用途：写前进提示词当验收标准、评审时作为「系统检测到的缺口」交给评审（避免只凭印象打分）、体检时聚合报给作者（按缺口类型聚合成「依据密度不足：第 2、4、7 节」，而不是每节每缺口各刷一条）。
  - **缺口分级**：只有高置信缺口才驱动整节重写（缺依据、计划论点没写出来、三处以上空话）；论证层数是启发式判断，只作为提示——误判一次就是一次白花钱的整节重写，比漏判更贵。
  - **rubric 评审 + 自动修订**（借鉴 AI-Scientist 的 reviewer）：六个维度（论证/证据/结构/术语/空话/引用）各 0~20 分，给出必须修正项；低于 70 分带着 mustFix 重写一次，不再复评（无限打磨成本不可控）。评审还会逐条检查必答子问题有没有被绕开（只给结论不给依据、用「有待观察」搪塞都算未回答），结果进 `unanswered` 并汇总到体检。全托管默认开启，共创可单节点。
  - **多轮深审的收敛条件**：打磨不是「跑满轮次」也不是「分数不涨就停」。只看分数会砍掉「缺陷在降、分数没动」的有价值的一轮（模型给分很粗：缺陷从 3 条降到 1 条，分数可能还是 85）。所以用双维度收敛——分数不涨**且**缺陷数没减少才停；取最优稿时先比缺陷数、再比分数。缺陷数 = 必修项 + 绕开的必答问题 + 未兑现的论点 + 高置信基准缺口。
  - **全文润色**（借鉴 AutoSurvey 的 refinement）：逐节带前后文重写衔接、去重复、统一术语，硬约束是不新增事实、不改引用编号、不动图表占位符、篇幅 90%~125%。后台任务，不阻塞页面。
  - **视角提问 → 研究纪要**（借鉴 STORM 的 perspective-guided question asking）：按政策/技术/市场/成本/风险等视角问出「素材答不出的问题」，再让模型以专家身份答一遍（答不了的标【待核实】），产出直接存成素材——「提问 → 研究 → 素材 → 引用」闭环。
- **公式**（论文/申报书/BP 必需）：正文里用 LaTeX 写——行内 `$...$`，独立成行的 `$$...$$`。识别与渲染在 `lib/math-tex.js` + `lib/doc-math.js`，零依赖自写解析器，覆盖上下标、分式、根式、求和/积分（上下限落在符号正上下方）、矩阵与 cases、希腊字母、`\text/\mathrm/\mathbb`、`\lim_{x\to0}`、重音、`\left(...\right)`；不认识的命令按正体文字呈现，不会让整条公式变空白。三路渲染同一份源码：**页面**出 MathML（浏览器原生渲染，不需要 JS 和字体文件）、**Word** 出原生公式对象（`m:oMath`，能选中、能改符号、能转 PDF，不是图片）、**Markdown** 保留 LaTeX 源码（GitHub/Typora/Obsidian 都认）。块级公式全文连号（式 1、式 2…，跨小节连续），居中排版、编号右对齐，`\tag{3.2}` 可指定固定编号。体检会报「定界符没配对」——`$` 个数是奇数时整段会被当成公式渲染成空白，这是最容易被忽略的坏稿。
- **跨节上下文**：写第 N 节时，注入全部前节的一句话要点（落库在 `doc_sections.summary`）+ 上一节结尾 420 字 + **前节已立论点链**与**已用过的素材编号**。原来每节只取前 500 字、总量 900 字，写第 8 节时基本看不到第 1 节立了什么论——论证断裂、前后重复、术语漂移都是这么来的。加上论点链与已用素材之后，本节知道「这些判断别再论证一遍」「这条数据前文用过了，能换就换」，从源头减少重复论证与重复引用。
- **百万字级语料上下文**（`lib/doc-context.js`）：素材语料可以到百万字量级，每节按需检索、分层装配，提示词仍然有界（标准档约 1.9 万字、深入档约 2.8 万字）。
  - **为什么不是「把百万字塞进提示词」**：百万汉字约 60~70 万 token，成本线性爆炸；而且长上下文中段的信息会被系统性忽略（lost in the middle）——模型看得见却不使用，等于花钱买噪音。所以做的是「语料百万级 + 上下文分层预算」。
  - **两阶段检索**：先把素材切成 700 字段落并预存 256 维向量（`doc_corpus` 表，1KB/块），检索时先向量粗筛候选（不读正文），再只对候选做 BM25 精排（含同义扩展与标题加权），最后按 `词面 0.6 + 向量 0.4` 混合打分。107 万字语料下索引 294ms、单节装配 240ms，不随语料线性膨胀。
  - **按方面分别粗筛**（多主题覆盖）：一节往往既有论点又有必答问题，主题可能不是一个。如果把整节压成一条混合向量，权重高的论点会占满候选池——实测 1M 语料下，「精密机床」的论点 + 「半导体材料」的必答问题，最后只剩精密机床有证据，稿子只回答了一半问题而评审以为「素材里没有」。所以每个查询方面各自取 top-N 再合并。
  - **稀有词门槛**（相关性）：公文与年报大量使用同一套模板句，所有段落的 BM25 分数都挤在一起，任何相对阈值都形同虚设——实测「20 条素材全部涌进来，连冷链物流都混进讲精密机床的稿子」。改成用 IDF 当门槛：段落必须至少命中一个「本节真正的主题词」（IDF 高于候选池中位数）才算相关，口径在不同语料上一致，不用调参。
  - **多查询**：检索词不是只有标题，而是「本节标题 + 本节要求 + 论题 + 论据要点 + 段落计划里的论点 + 必答子问题」。论点权重最高（1.3）——它比标题具体得多，是「这一段该引哪条素材」的真正依据。
  - **四层装配**：① 文档记忆（前节论点、已用数据、章节术语，恒定 3000 字，不随节数增长）；② 相关证据（按预算给 10~30 段）；③ 语料地图（全部素材的概览 + 本节是否命中，让模型知道自己还有什么没用）；④ 邻近上下文（核心来源的前后段落，避免碎片引用导致「引了但没读懂」）。
  - **去重按数据判、不按文字判**：真实语料里同一段话常被多份素材重复收录（多份年报的模板段落、论文预印本与正式版），不去重会让名额全被几份几乎一样的素材占满。但只用文字相似度去重是错的：两份年报模板相同、只有数字不同，相似度轻松过 0.9——按相似度一刀切就把第二份的真实数据丢了。判据改成「两段都带数字且数字完全相同才算重复；数字不同一律保留」，并在概览里说明「另有 N 段因高度重复未注入」。
  - **用量可见**：每节写作时把「语料多大、命中哪几条素材、注入多少字、预算用掉几成、去重几段」落库（`doc_sections.context_json`），页面「🧠 本节上下文」卡直接显示。预算用不到四成时会说明原因（语料里相关内容不多，或大量重复被去重），而不是让作者猜。没有这张卡，百万字语料和两千字检索在界面上长得一模一样。
  - **作者可强制指定**：在「本节要求」里写「重点用 M7」，该素材的前两段会优先纳入，且不受「每条素材最多 3 块」限制。百万字语料下检索偶尔会漏掉作者最在意的那一条，给一个显式入口比调参可靠。
  - **增量索引**：按素材内容哈希比对，没改过的素材不重切、不重算向量（107 万字语料首次索引 175ms，无变更时 40ms 以内）。素材删除时同步清理语料块，避免正文引用到已不存在的编号。
  - **与小说工作台的关系**：只复用 `lib/vector-store.js` 的**纯函数原语**（哈希向量、token 估算），不复用它的 `syncBook`/`retrieve`（绑在「书 + 磁盘文件」上）。索引表、缓存、预算全部独立，小说的 `kb_chunks` 与检索链路一行未改（有回归测试断言 `ENGINE` 标识不变、文档语料不写 `kb_chunks`）。
- **篇幅下限落库**：类型自带的小节下限（论文「结果与分析」1600 字、可研「建设方案」1000 字、通知「通知事项」700 字）写入 `doc_sections.min_chars`，共创落稿门禁与全托管门禁按同一口径执行。
- **全文体检**：见上文「成稿体检」，入口是工作区顶部的「📐 全文体检」卡。
- **导出**：全文 Markdown（`.md`）与 Word（`.docx`）。Word 导出走 `lib/docx-export.js` 自建 OOXML 包（复用 `lib/zip.js` 的 `makeZip`，不引第三方依赖）：标题页、A4 页边距、宋体正文首行缩进、黑体分级标题、表格带边框、`**粗体**`/`` `行内码` `` 保留、图表为原生 DrawingML 对象、公式为原生 OMML 对象，文件名用 RFC 5987 编码，下载下来就是文档标题。
- **任务状态**：文档任务与小说任务同页展示（`/status`，进度单位为"节"），续跑入口通用。
- **技能广场（本地版）**：`/skills` 浏览全部官方内置与自建技能、启停、新建（名称/类别/模板）、导出 Markdown。官方云端广场离线不可用，本地广场即替代。
- **数据**：`doc_projects` / `doc_sections` / `doc_materials` 表 + 导出 Markdown / Word；删除项目会连带清理状态机记录。

## 目录结构

```
replica/
├── server.js            主服务（静态前端 + IPC 后端，零 npm 依赖）
├── config.json          你的 API 配置
├── lib/                 glue(shim)/db/llm/prompts/书源/命令注册
├── web/                 解包出的官方前端（index.html 被服务注入 Tauri 胶水）
└── data/                SQLite 数据库、提示词库、书源配置、书籍正文、备份
```

- 数据库：`data/writerx.db`（历史兼容文件名；设置 + 25 个技能模板已就位）
- 书籍文件：`data/books/<bookId>/设定|细纲|正文|参考/*.md`
- 数据全在本机；想搬家：备份 `data/` 目录即可。

## 常见问题

- **界面提示"未配置可用模型渠道"** → 检查 config.json 的 apiKey 或去 设置→渠道管理 配置并设为当前。
- **模型接口报错 4xx/5xx** → 服务端日志（终端窗口）会打印具体错误；确认 baseUrl 是 OpenAI 兼容格式且 key 有效。
- **想用官方没列出的站点做书源** → 在 `data/sources.json` 按现有格式加（搜索/目录/正文选择器），重启生效。
- **端口被占用** → `node server.js 17382`（第二个参数改端口）；浏览器对应改访问端口。

## 技术说明（备忘）

- 前端通过注入的 `window.isTauri=true` + `__TAURI_INTERNALS__.invoke` 胶水（见 `lib/glue.js`）把全部
  Tauri IPC 转成 `POST /ipc/<cmd>`（服务器注入进 index.html，前端零改动）。
- 流式（AI 生成）走同连接 NDJSON：通道事件逐行下发，最后一行是结果；胶水按 channel id 分发回 `onmessage`。
- 数据库由 node:sqlite 驱动（Node 22+ 内置，无需编译）。
