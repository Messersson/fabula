# Fabula 离线版（不打包 · 不依赖官方账号/API）

Fabula 是一个**纯本地 Web 写作应用**：
前端资源解包自官方 exe（原样未改），后端用 Node 零依赖实现替代 Rust 侧；
**AI 调用全部走你自己的 API（任何 OpenAI 兼容渠道）**，不连 mochang 的 hub，
不需要注册、不需要授权码、不产生任何费用到官方。

## 离线版 vs 官方版（重要差异）

- **无内置模型**：官方"内置免费模型/会员专供模型"依赖 mochang 服务器，离线版已整体移除（模型列表只显示你自己配置的渠道，"内置模型"区显示"暂无可用模型"）。
- **无登录/会员系统**：账号区显示本地身份"本地版"，不出现"点此登录/注册"、会员购买入口；欢迎弹窗自动关闭。
- 其余功能（AI 写作、书籍、技能、书源、导出等）与官方一致，全部本地运行。

## 快速开始

```bat
cd C:\path\to\Fabula
node server.js
```

浏览器打开 **http://127.0.0.1:17381/** 即可使用。
（双击 `start.bat` 也可以。）

## 把 API 换成你的（二选一，效果一样）

### 方式 A：修改 config.json（推荐，改完重启服务）
```json
{
  "activeChannelId": "ch_mine",
  "channels": [
    {
      "id": "ch_mine",
      "label": "我的API",
      "baseUrl": "填你的 OpenAI 兼容接口根地址",
      "modelsUrl": "可选：填你的模型列表地址",
      "model": "填你的模型 ID",
      "apiKey": "sk-你的密钥"
    }
  ]
}
```
- `baseUrl` 由用户自己填写 OpenAI 兼容接口的地址（DeepSeek / Kimi / 智谱 GLM / 通义千问 / 火山方舟 / MiniMax / 硅基流动 / OpenAI 都行）。
- 改完 **重启 node server.js** 生效（不会覆盖你在界面里改过的配置）。
- 也可以用 `modelsUrl` 自动拉取 /models 模型列表。

### 方式 B：界面里配（设置 → 渠道管理 → 添加渠道）
预设列表里已内置 9 个厂商（DeepSeek、Kimi、通义千问、智谱、火山方舟、MiniMax、硅基流动、OpenAI、自定义），
选一个 → 填 Key → 保存 → 设为当前渠道。应用内所有 AI 功能立即走你的渠道。

## 上下文与向量库能力

- 资料库仍是本地 Markdown 文件树；同时新增了本地向量知识库，数据保存在 `data/writerx.db` 的 `kb_files` 与 `kb_chunks` 表中。
- 正文按**场景**切片（360–1,200 字符，优先在空行与场景切换处断开），每片携带章号、出场人物、地点和关联伏笔；设定类文件仍按 1,400 字符、220 字符重叠切分。检索采用 SQLite FTS5 三元组全文索引与 256 维本地哈希向量的混合候选，再加实体/时间/伏笔过滤与重排。FTS 保住人物名、专有名词和原句，哈希向量补足周边词面关联；它不调用第三方 embedding 服务，书稿不会因索引离开本机。
- 检索打分在进程内的向量矩阵上完成（整书向量一次性装入连续 `Float32Array`），正文只按入选片段取一次；一本百万字长篇的热查询约 6–9 ms。索引变化通过版本号 + 短 TTL 失效，写入路径会显式丢弃矩阵。
- 文件保存、改名、删除会增量更新索引；章节摘要 Markdown 的追加只索引新增尾段，旧章修改时才全量重建。若发现片段数量与元数据不一致，追加会自动回退为全量重建。首次对话会自动补齐已有书稿的索引，也可调用 IPC `rebuild_knowledge_index` 强制重建整书索引。
- 全 AI 托管采用滚动规划：先根据《世界观》《人物库》《剧情大纲》生成当前 20 章窗口的 `章节规划.md`，再逐章生成细纲与正文；不会预先生成全书细纲，因此可随时中断并从下一章续写。
- 每章完成后会把摘要、人物/时空/事实/线索状态写入 SQLite；下一章同时参考上一章正文结尾、最近摘要、长期连续性状态和下一章细纲。人物上下文按核心人物优先并限制为最多 24 人；每完成 50 章会生成一卷摘要，供后续章节压缩回顾。
- 章节规划、章节摘要、连续性状态和卷摘要均按章或按卷落库；Markdown 文件仍是可编辑的本地副本，数据库负责长篇生成时的小窗口查询。批量续写默认保留任何非空已有正文，只有显式选择覆盖才会重写。
- 章节摘要追加前会记录旧文件长度并设置中断标记；如果进程在追加后、状态提交前退出，重启时会截断到旧长度后重放，避免重复章节。重写旧章时，人物、事实、时空和伏笔会按目标章节重放，不会混入后续剧情。
- 启动全 AI 托管前可以选择本书文风卡、主写法和最多 6 个叠加技能；这些配置会写入本书，之后章节规划、细纲和正文生成都会自动使用。
- 每次 AI 写作都会按当前请求和最近会话召回最多 8 个相关片段，最多加入约 10,000 字符；手动勾选的资料仍保留，最多 8,000 字符。
- 会话历史会附带最近 12 条用户/助手消息，每条最多 6,000 字符。
- 这套索引和分层记忆可支撑百万字小说的长期检索与渐进式写作，但不等于“百万字全文一次性塞进模型上下文”。生成时只装载当前规划窗口、最近摘要、长期状态、卷摘要和相关检索片段；建议总纲按“总纲 -> 分卷 -> 章节 -> 正文 -> 归档”维护，以便在数十万字后仍能稳定回收早期伏笔。
- 人物别称从《人物库》自动建立同义族（支持 `## 沈砚`、`## 沈砚（墨七）`、`## 沈砚 | 墨七`、`**沈砚**（墨七）`、`- 别名：墨七、断水客` 等写法），查询时双向展开，所以正文只写「墨七」也能被「沈砚」召回。
- 当前哈希向量是本地词面相似度，不是语义 embedding，因此纯同义改写和隐喻关联仍可能漏召回。
- **语义召回（可选，embedding 叠加层）**：在设置里配置 `embedding_model`（走你当前渠道的 OpenAI 兼容 `/embeddings`，如 SiliconFlow 的 `BAAI/bge-m3`、`BAAI/bge-large-zh-v1.5`，也可用 `embedding_base_url` / `embedding_api_key` 覆盖地址与密钥）即可启用。片段向量懒填充进 `kb_embeddings` 表（首次检索顺手补齐，或调 `prime_embeddings` 一次性预热）；全书片段都有同一模型的向量后，检索的"向量分量"自动切换为语义余弦，与 FTS 词面分、人物/伏笔命中继续混合打分。任何一步不可用——未配置、接口失败（60 秒断路冷却）、只填充了一部分——都整本无缝回落到本地哈希引擎，两个向量空间绝不混算；换模型时旧向量自动清空重填。IPC：`get/set_embedding_config`、`prime_embeddings`。选型说明：本地跑 bge-small-zh 需要引入 onnxruntime 等原生依赖，与本项目"零 npm 依赖、纯离线"的约束冲突，因此选择走你已配置渠道的 embeddings 接口（bge 系列在各聚合网关通常免费或近似免费），哈希引擎作为永远可用的兜底。

## 无人值守长跑

批量生成正文（`batch_generate_bodies`）和全 AI 托管（`batch_generate_full`）都支持长时间无人值守，相关参数：

| 参数 | 默认 | 作用 |
|---|---|---|
| `recoverMode` | `auto` | `stop` 任一章失败即停；`skip` 隔离后永不因单章失败停；`auto` 隔离后继续，连续失败达到阈值才停 |
| `maxConsecutiveFailures` | `2` | `auto` 下的停机阈值。单章失败多半是这一章的问题，连续失败多半是渠道/配额/上下文问题 |
| `maxRetries` | `3` | 每章的重试次数（指数退避，尊重接口返回的 `Retry-After`） |
| `escalateRetry` | `true` | 重写时把上次被判不合格的原因写回提示词，而不是原样再问一遍 |
| `maxTokensPerChapter` | 目标字数 × 1.5 + 8000，再 × 6 | 单次尝试的 token 上限，用于识别「越写越长」的失控；触发后该章隔离且不重试 |
| `maxTokensPerRun` | `0`（全托管为 800 万） | 整轮 token 上限；超限时**保留断点暂停**（`paused_budget`），可续跑而不是失败 |

- **状态页**：浏览器打开 `http://127.0.0.1:17381/status`，可以看到每个任务的状态、进度、token 消耗、被隔离的章节及原因，并直接点「从断点续跑」。页面 15 秒自动刷新，由服务端直接渲染（不依赖前端构建产物）。
- **续跑**：`resume_generation_run` 会从第一个未提交的章节继续，把被隔离的章节重新排队，并复用原来的任务（token 账目和失败原因不会断成两段）。已提交的章节不会被覆盖。
- **生成日志**：每轮结束（含取消和异常）都会把结果追加到作品的 `设定/生成日志.md`：新建/跳过几章、哪几章被隔离及原因、花了多少 token、为什么停机。
- **一致性审计**：每 10 章做跨章审计、每 50 章做卷级审计（跨章重复桥段、章末钩子缺失、核心人物断层、篇幅漂移、未回收伏笔积压、**世界规则禁词**、**正典事件复现**），结果追加到 `设定/一致性报告.md`。审计只报告，不阻断生成。
- **世界规则 / 正典事件**：两张硬约束表——`世界规则.md`（全书不得违背的设定铁律，可附 `禁词：` 供审计逐字排查）与 `正典事件.md`（已锚定章节的正典事件，后续章节不得矛盾或复现，`关键词：` 供卷级审计检测远期复现）。文件在作品的 `设定/` 组里直接编辑，也走 IPC（`get/save/delete_world_rule`、`get/save/delete_canon_event`）；**全托管与 AI 共创两条路径都自动注入**（细纲/正文批量、自由对话、智能写作、场景生成；未来章节的事件不提前泄漏，自由对话取"站在最新进度"视角）。交互保存正文（save_doc / save_section）会自动补齐长期记忆（章节摘要/连续性），与批量路径共享同一套世界状态。审计确定性排查禁词与事件复现；禁词 ≥2 字、指纹短语 ≥6 字，否则容易误报。
- **500 章端到端仿真**：`test/longform-simulation.test.js` 用桩模型把全托管状态机连跑 500 章验证到底——中途注入单次失败升级重试（第 50/150/400 章）、永久失败隔离（第 100/300 章）、两次预算暂停与续跑收尾，断言 500 章全部提交、三段共用同一个任务、token 账目与桩的实际调用次数分毫不差、已提交章节零重做。`npm test` 总耗时约 1 分半，其中其余 81 个测试约 10 秒。

## 文档工作台与技能广场

小说之外的第二条产品线，与小说创作完全隔离（平行引擎、平行页面，小说管线一行未动）：

- **入口**：主界面右下角常驻 dock（文档工作台 / 技能广场 / 任务状态），或直接访问 `http://127.0.0.1:17381/docs`。
- **文档类型**：商业计划书、项目申报书、调研报告、学术论文、法律合同（共创建议）内置小节结构与文体卡；自定义类型上传模板（.md/.txt，按 Markdown 标题或中文序号切分小节；浏览器本地读取后提交，不经第三方）。
- **两种写作方式**：AI 共创（逐节起草 / 按指示修改 / 手工编辑落盘）与 AI 全托管（整篇批量，逐节质量门禁、失败隔离、连续失败停机、token 预算暂停、断点续跑——与小说管线同一套 orchestrator 状态机与语义）。合同草稿仅作辅助，页面与导出文件均提示签署前需专业人士审核。
- **任务状态**：文档任务与小说任务同页展示（`/status`，进度单位为"节"），续跑入口通用。
- **技能广场（本地版）**：`/skills` 浏览全部官方内置与自建技能、启停、新建（名称/类别/模板）、导出 Markdown。官方云端广场离线不可用，本地广场即替代。
- **数据**：`doc_projects` / `doc_sections` 表 + 导出全文 Markdown；删除项目会连带清理状态机记录。

## 目录结构

```
replica/
├── server.js            主服务（静态前端 + IPC 后端，零 npm 依赖）
├── config.json          你的 API 配置
├── lib/                 glue(shim)/db/llm/prompts/书源/命令注册
├── web/                 解包出的官方前端（index.html 被服务注入 Tauri 胶水）
└── data/                SQLite 数据库、提示词库、书源配置、书籍正文、备份
```

- 数据库：`data/writerx.db`（历史兼容文件名；设置 + 25 个技能模板已就位）
- 书籍文件：`data/books/<bookId>/设定|细纲|正文|参考/*.md`
- 数据全在本机；想搬家：备份 `data/` 目录即可。

## 常见问题

- **界面提示"未配置可用模型渠道"** → 检查 config.json 的 apiKey 或去 设置→渠道管理 配置并设为当前。
- **模型接口报错 4xx/5xx** → 服务端日志（终端窗口）会打印具体错误；确认 baseUrl 是 OpenAI 兼容格式且 key 有效。
- **想用官方没列出的站点做书源** → 在 `data/sources.json` 按现有格式加（搜索/目录/正文选择器），重启生效。
- **端口被占用** → `node server.js 17382`（第二个参数改端口）；浏览器对应改访问端口。

## 技术说明（备忘）

- 前端通过注入的 `window.isTauri=true` + `__TAURI_INTERNALS__.invoke` 胶水（见 `lib/glue.js`）把全部
  Tauri IPC 转成 `POST /ipc/<cmd>`（服务器注入进 index.html，前端零改动）。
- 流式（AI 生成）走同连接 NDJSON：通道事件逐行下发，最后一行是结果；胶水按 channel id 分发回 `onmessage`。
- 数据库由 node:sqlite 驱动（Node 22+ 内置，无需编译）。
